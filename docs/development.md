# Разработка

## Как Next общается со Steam

- **Один постоянный помощник Steamworks** вместо нового процесса на каждый запрос: Steam инициализируется один раз, пока открыта Forts, запросы идут по очереди с паузой между ними. После трёх сбоев подряд помощник отдыхает и не долбит Steam повторами.
- **Имена и ссылки на аватары** сохраняются в `MatchroomNextData/steam-profiles.json`. Интерфейс использует их до недели без повторных запросов и показывает последние известные данные, пока Steam недоступен. Запросы на steamcommunity.com идут с интервалом не менее 2,5 секунд. При отказе Next ждёт срок из ответа Steam, а если его нет — от двух минут с увеличением паузы до получаса.
- **Радар** проверяет рейтинг и активность через клиент Steam по прежнему расписанию. Дополнительная проверка публичных профилей теперь идёт по одному игроку раз в 25 секунд. Присутствие игроков, которых клиент Steam не видит, может определяться реже. Ограничение на загрузку профилей больше не показывает общую полоску на всех экранах.

## Запуск исходников

- **DEMO.cmd** — интерфейс на вымышленных данных (48 матчей, 7 соперников, 9 комнат), без Steam и без записи на диск: профиль окна создаётся во временной папке.
- **START.cmd** — работа с настоящими реплеями. Нужен Python 3.10+. Для рейтинга нужны работающие Forts и Steam, для профилей — интернет.

Ключи запуска: `--browser` — открыть в браузере вместо своего окна; `--no-browser` — без окна (тесты).

## Исходники

- `web/` — клиент: `index.html`, `css/` (токены, база, компоненты, экраны), `js/` (модули), `tests/`.
- `shell/` — нативная оболочка на C# (WebView2), `shell/lib/` — библиотеки WebView2 (лицензия Microsoft рядом).
- `app_server.py` — локальный HTTP-сервер и API; `steam_service.py` — единый шлюз к Steam; `app_window.py` — запасное окно Edge для запуска из исходников.
- `desktop_app.py`, `forts_replay.py`, `match_history.py`, `steam_data.py`, `ranked_radar.py`, `lobby_service.py` — backend рабочей версии.
- `windows_notify.py` — уведомления Windows: когда показывать, тексты RU/EN, клик; `lobby_native/ToastHost.cs` — показ toast.
- `demo.py` — тот же клиент и API на вымышленных данных в памяти.

## Пересборка EXE

Нужен PyInstaller в Python 3.13. Анализатор реплеев собирается отдельно (нужен Go 1.27+) и кладётся в `fwr/fwr.exe`:

```bash
git clone --branch v0.6.0 https://github.com/an0nfunc/forts-replay
cd forts-replay && go build -trimpath -ldflags "-s -w" -o ../fwr/fwr.exe ./cmd/fwr
```

 Сборщик включает только исходники и ресурсы (без тестов клиента и пользовательских данных):

```bash
py -3.13 build_exe.py
```

Сборка в два шага (PyInstaller собирает службу, csc из Windows собирает оболочку и встраивает в неё службу и WebView2). Результат: `Matchroom Next v0.14.0.exe` и контрольная сумма SHA-256.

При выпуске следующей версии: обновить версии в desktop_app.py и build_exe.py, собрать EXE и опубликовать релиз с тегом vX.Y и файлами Matchroom.Next.vX.Y.exe и Matchroom.Next.vX.Y.sha256.txt. В файл контрольной суммы запиши SHA-256 EXE. GitHub должен показывать SHA-256 файла; без него обновление будет отклонено.

## Ограничения данных

Ограничения исходной программы сохраняются: поддерживается FWR format 5, импортируются рейтинговые реплеи с номером сезона в имени; Steam не предоставляет идентификатор матча для точного расчёта дельты. Отсутствие сигнала радара не означает безопасного соперника.
